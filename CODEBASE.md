# Кодова база OVDP Manager

Це карта коду для мобільного застосунку Expo SDK 58 на iOS та Android. Маршрути працюють через Expo Router, тема — через Unistyles 3, HTTP-запити до НБУ — через Axios, а локальний стан — через Zustand з `persist` поверх MMKV. Веб-платформу не налаштовано.

## Шари

| Шлях                                          | Призначення                                                                                                                                          |
| --------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| `index.ts`                                    | Спершу реєструє тему Unistyles, потім запускає Expo Router.                                                                                          |
| `src/app/`                                    | Тонкі входи маршрутів. Кожен екран рендерить компонент із `pages`; `_layout.tsx` визначають Stack і Tabs.                                            |
| `src/pages/payments/`                         | Вкладка «Виплати»: верхні вкладки «Майбутні» (`/`) і «За рік» (`/year`, підсумки й графік), фільтри для обох.                                        |
| `src/pages/holdings/`                         | Гаманець; картка ОВДП одним екраном: параметри, підсумок, покупки, виплати; додавання в активний план: вибір ОВДП (`/add`), покупка (`/add/[isin]`). |
| `src/pages/plan/`                             | Вкладка «Плани»: підсумок активного плану; «Мої плани» (`/plan/list`) — перемикання та створення; назва плану, вона ж перший план (`/welcome`).      |
| `src/pages/settings/`                         | Налаштування: копія та відновлення, тема.                                                                                                            |
| `src/pages/backup/`                           | Екран відновлення з копії: файл або вставлений JSON.                                                                                                 |
| `src/features/`                               | Сценарії додавання покупки, планування, роботи з копіями та фільтрів виплат; UI цих сценаріїв належить сторінкам.                                    |
| `src/entities/portfolio/`                     | Типи й обчислення облігацій, покупок і позицій, сховище покупок, каталог НБУ, `useWallet` і спільні блоки екранів.                                   |
| `src/shared/api/`                             | Axios-клієнт НБУ.                                                                                                                                    |
| `src/shared/ui/`, `lib/`, `theme/`, `config/` | Базові компоненти, утиліти, тема Unistyles і ресурси застосунку.                                                                                     |

Зовнішні імпорти проходять через `index.ts` зрізу. Усередині зрізу використовуються відносні імпорти. Шари залежать лише від нижчих: `app` → `pages` → `features` → `entities` → `shared`. Steiger перевіряє ці межі через `yarn lint:fsd`. Евристика `insignificant-slice` вимкнена для `features`: у цьому невеликому застосунку кожен сценарій має один екран входу.

Кожен React-компонент має окремий `.tsx` файл. Допоміжні компоненти лежать поруч з екраном або базовим UI, який їх використовує; у `src/app/` залишаються тільки маршрути. Типи й утиліти, спільні для кількох компонентів, лежать в окремих `.ts` файлах.

## Стилі

- Кожен компонент має власний `StyleSheet.create((theme, rt) => …)` з `react-native-unistyles`: кольори теми й відступи safe area (`rt.insets`) потрапляють у стилі без ререндерів. Стани компонента (варіант кнопки, тон тексту) — це `variants` і `styles.useVariants()`.
- Токени теми: відступи `theme.space` (сітка 4 pt: `xxs` 2 … `xxxl` 48), радіуси `theme.radius` (`xs` 4, `sm` 8, `md` 12, `lg` 16, `full`), тіні `theme.shadowCard` і `theme.shadowRaised` (`boxShadow`). Відступи й радіуси спільні для тем і лежать у `src/shared/theme/tokens.ts`; статичні стилі (`screenContent`, відступи FAB) імпортують `space` напряму. Рядки й край екрана — `lg` по горизонталі та `md` по вертикалі, секції — через `xl`. Тінь і `overflow: 'hidden'` ніколи не стоять на одному `View`: зовнішній відкидає тінь, внутрішній обрізає (`Section`, `SectionCell`).
- Палітра (`palette.ts`) зібрана з кольорів #046865, #21A0A0, #E53D00, #000000, #FCFFF7: темна бірюза — дії та дохід, цинобра — кнопка «+», покупки й видалення. Текстові пари проходять WCAG AA; кольори серій графіка перевірено валідатором палітри (яскравість, насиченість, розрізнення при дальтонізмі).
- Кольори в пропсах, які не є стилем (`tintColor`, `placeholderTextColor`), передає `withUnistyles`. `useUnistyles()` лишається тільки для опцій навігаторів у `src/app/`.
- Тему обирають у налаштуваннях: `src/shared/theme/preference.ts` зберігає вибір під `theme-preference-v1` і застосовує його до Unistyles (`adaptiveThemes` для системної, `setTheme` для явної) та до `Appearance`, щоб нативні контроли мали ту саму тему. `unistyles.ts` читає збережений вибір до `StyleSheet.configure`.
- Верхні вкладки — навігатор `TopTabs` із `src/shared/ui/navigation/TopTabs.tsx` (`expo-router/js-top-tabs` поверх `react-native-tab-view` і `react-native-pager-view`): кольори теми, «назад» закриває екран, а не гортає вкладки. Зараз вони є лише у «Виплатах»; кожна вкладка — окремий маршрут. `lazy` вимкнено навмисно: з лінивими вкладками expo-router 58 змінює ключ маршруту при першому відкритті, і pager перескакує на іншу вкладку. Кольори навігації (`ThemeProvider` у `src/app/_layout.tsx`) беруться з палітри Unistyles.
- Іконки — набір Ionicons з `@react-native-vector-icons/ionicons/static`: шрифт вбудовує config-плагін пакета з `app.json`, тож іконки малюються з першого кадру. Компоненти беруть `ThemedIcon` (`src/shared/ui/icon/`), колір задає `uniProps`; назви типізовано як `IconName`. Іконка вкладки заповнена, коли вкладку вибрано, і контурна (`-outline`) в інших випадках.
- Кольори серій графіка задаються ключами `SeriesColor` (`coupon`, `nominal`, `purchase`) з `src/shared/theme/series.ts`, а не рядками кольорів.

## Дані та зберігання

- Zustand `persist` зберігає дані в `react-native-mmkv` через синхронний адаптер із `src/shared/lib/storage.ts`, обгорнутий у `createJSONStorage`. Міграцій зі старих сховищ немає: дані переносяться через резервну копію.
- Дані ззовні — відповідь НБУ та файл резервної копії — перевіряються схемами zod. Покупки зі сховища теж читаються через `PurchaseSchema` (`merge` у `persist`): пошкоджений запис пропускається, а не ламає розрахунки всього гаманця. Схеми покупки — `src/entities/portfolio/model/purchase.schema.ts`; повідомлення `PurchaseInputSchema` показуються користувачу, коли копію відхилено.
- Застосунок ще не випущений і ставиться на чисті пристрої, тому сховища не мають `version`/`migrate` і не читають старих форм даних. Якщо форма змінюється, сховище просто починає з порожнього стану. Dev-гілок (`__DEV__`) і моків у застосунку немає.
- `src/entities/portfolio/model/purchases.store.ts` зберігає покупки під ключем `holdings-v1`; ключі сховищ не перейменовуються.
- `useWallet()` поєднує покупки з даними НБУ: позиції, їхні виплати й події покупок. Екрани беруть дані з нього, а не перераховують виплати самі. `WalletGate` показує порожній гаманець або очікування даних НБУ однаково на всіх екранах.
- Кожна покупка в гаманці належить плану (`WalletPurchase.planId`). Поки планів немає, кореневий `_layout.tsx` через `Stack.Protected` пускає лише на екран першого плану (`/welcome`) і відновлення з копії. Активний план обирається на екрані «Мої плани» (`/plan/list`, кнопка в заголовку вкладки «Плани») і зберігається під `active-plan-v1` (`activePlan.store.ts`), тож відкривається й при наступному запуску; якщо план видалено, активним стає перший. Новий план одразу стає активним. `useWallet()` і `WalletGate` бачать лише покупки активного плану. Видалення плану видаляє і його покупки в гаманці.
- Плани зберігаються під `investment-plan-v1` у `entities/portfolio/model/plan.store.ts`. План — це лише `{ id, name }`; його покупки — це покупки гаманця з його `planId`, і окремого списку запланованих покупок немає. Покупка може мати будь-яку дату від розміщення до погашення: майбутня вважається запланованою (позначка «заплановано» в гаманці) і дає виплати лише після своєї дати. Усі покупки додає одна форма `/add/[isin]`: дата, кількість і сума, яку заплатили за всю покупку; ціна 1 шт = сума ÷ кількість і лише показується. Вкладка «Плани» підсумовує активний план функцією `planTotals`: вкладення, купони, погашення, результат і дохідність за весь строк, а не річна ставка. Для неповного графіка НБУ результат і дохідність не показуються.
- `src/features/payment-filters/` зберігає фільтри майбутніх виплат під `payment-filters-v1`: тип, період, валюту й ОВДП. Порожній список ОВДП означає «усі». Перед застосуванням `effectiveFilters` відкидає ОВДП і валюти, яких уже немає серед майбутніх виплат, тож збережений фільтр не ховає все.
- Повідомлення про події показує toast: `showToast` з `@/shared/lib` (`toast.store.ts`), а малює його `ToastHost` з `shared/ui/toast`, підключений один раз у `src/app/_layout.tsx`. Він з'являється згори під статус-баром, тримається 4 с (6 с, якщо має дію) і закривається дотиком; новий toast замінює попередній. Toast показують: невдале оновлення даних НБУ поверх кешу (з дією «Повторити»; без кешу помилку й повтор показує сам екран), і результати дій з копіями. Підтвердження небезпечних дій лишаються `Alert` (`confirmDestructive`), а стани, що тривають, — підписами на екрані.
- Форми (покупка, назва плану, вставлений JSON копії) працюють на `react-hook-form` із `zodResolver` у режимі `onChange`. Схема zod перетворює текст полів на значення (`z.input`/`z.output` у типах `useForm`) і містить повідомлення для користувача; схема, що залежить від даних, — це фабрика поруч із хуком форми (`purchaseFormSchema(bond)` перевіряє дату в межах життя ОВДП). Кнопка збереження вимкнена, доки форма невалідна, а помилка поля з'являється після його зміни: під рядком (`FieldRow`) або в підписі секції під блоковим полем. Помилка розбору вставленої копії теж показується під полем. Стан форми читається через `useFormState({ control })`, значення — через `useWatch`, а не з `form.formState`, який React Compiler закешував би.
- Дати всюди зберігаються й порівнюються як рядки `YYYY-MM-DD`, як їх віддає НБУ. `date-fns` використовується лише в `src/shared/lib/date.ts`: форматування, сьогоднішня дата, різниця в днях. Нову роботу з датами додавайте туди ж, у локальному часі.
- `src/entities/portfolio/api/` завантажує каталог облігацій і графіки виплат НБУ через спільний Axios-клієнт; локальний кеш зберігається під `nbu-bonds-v1`. Екран, що відкривається, сам оновлює дані, якщо їм понад 6 годин; після невдалої спроби наступна автоматична буде не раніше ніж за 5 хвилин. Запит, що вже йде, повторно не запускається: `refresh` чекає на нього. Спінер `RefreshControl` бере стан з `usePullToRefresh` (`shared/lib`) і показується лише тоді, коли користувач сам потягнув список, а не під час фонового оновлення.
- `src/features/backup/model/backup.ts` перевіряє та створює JSON-копії; файлові дії — у `api/backupFile.ts`. Особиста копія `src/ovdp-backup-*.json` ігнорується Git та не є частиною коду.
- JSON-копія версії 5 містить `holdings` (усі покупки з `planId`) і `plans` (лише назви); відновлення йде через `restorePortfolio`. Читається лише ця версія: `parseBackup` перевіряє `format` і `version`, вимагає хоча б один план і план для кожної покупки. Відновлення замінює всі плани та покупки.

Ресурси іконок лежать у `src/shared/config/app-icon/`; посилання на них визначено в `app.json`. Нативні каталоги `ios/` і `android/` генерує Expo, їх не слід редагувати вручну.

## Перевірка

`yarn validate` запускає Prettier, ESLint, Steiger і TypeScript. `npx expo export --platform ios` та `--platform android` перевіряють складання JS-бандлів; вони не замінюють запуск на пристрої.
